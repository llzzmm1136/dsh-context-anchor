# Context Anchor · 上下文锚点

给 DeepSeek Harness 装一块「长时记忆」：每一步都从**完整会话日志**重建注意力锚点，并用本地检索内核在被压缩掉的历史里找回原文——超长会话不再失忆。

---

## 它解决什么问题

DSH 的上下文窗口再大也有上限。一旦历史被压缩（compaction），模型就只看得见一份摘要：早先的决定、路径、命令、报错原文全部退出表层。后果是重复问已答过的问题、改回已否掉的方向、找不到之前写过的文件。

这个插件把**会话日志**当作唯一真相：压缩只改表层，不改日志。于是它做三件事：

1. **每步重建锚点**——不依赖摘要，直接从日志重算当前主线、任务清单、涉及文件、上一步动作，注回系统提示。
2. **本地检索内核**——模型发一条检索指令，内核在倒排索引上排序，返回原文片段与 `seq` 编号；模型再按 `seq` 精确回读。
3. **自动压缩 + 自动回忆**——到阈值自动压缩，不等用户开口；一旦有历史离开表层，就把与当前任务最相关的归档片段自动摆回锚点。

---

## 能力一览

| 能力 | 说明 |
| --- | --- |
| 上下文锚点 | 每步重建，默认上限 1000 字符：主线指令、任务列表、涉及文件、上一步动作、少量自动回忆 |
| `context_recall` | 检索内核：倒排索引 + BM25 排序，支持短语、排除词、类型/工具/文件/seq 过滤 |
| `context_expand` | 按 `seq` 区间逐字读取完整日志（含被压缩隐藏的部分），默认单次 4000 字符 |
| `context_memory` | **分类记忆**：日志到达时按固定规则自动归类成七类，模型按需读取，不必先检索 |
| 自动压缩 | 热上下文达到设定百分比时自动把旧表层折成一条检查点 |
| 自动回忆 | 有内容离开表层后，每步最多带回 2 段强相关归档原文；弱匹配不注入 |
| 界面 | 输入框下方「本地缓存 ~N」徽标（绿/黄/橙随压力分级）；点开面板看状态、可召回内容、检索次数、热上下文与降智水平、缓存占用趋势图、下次压缩会归档哪一段，并可切自动/自定义阈值、重置为全局、导出/导入设置 |

## 安装

**方式一：仓库地址（推荐）**

DSH 侧栏 → **插件** → **添加插件**（或箭头 → 安装第三方插件）→ 粘贴：

```
https://github.com/llzzmm1136/dsh-
```

安装后点**立即启用**，然后**重启 DSH**。

**方式二：npm 包**

```bash
npm pack        # 仓库根目录，产出 dsh-context-anchor-x.y.z.tgz
```

插件页粘贴该 tgz 的绝对路径安装，同样需要启用并重启。

> 为什么必须重启：主机端与客户端两半都在启动时加载，页面刷新不会重新加载插件模块。

## 首次使用

1. 打开任意会话，输入框下方出现「本地缓存 ~N」。
2. 点击它：面板显示状态、可召回内容、检索次数、热上下文占用、降智水平与压缩策略。
3. 问模型一件它早该忘记的事，例如「我最开始让你改哪个文件？」——它会调用 `context_recall` 去找。

压缩生效后，`~/.dsh/storages/context-anchor/trace.jsonl` 会逐条记录判定（`below` / `compacted` / 无服务等）；排查「为什么没压缩」直接看它。

## 检索语法

`context_recall` 的 `query` 既可以是关键词，也可以带结构：

```
温度 曲线 type:assistant after:100   # 只看助手消息、seq > 100
"精确短语" -排除词                     # 短语加权命中，排除词过滤
tool:read file:Temperature            # 只看 read 工具、且提到该文件的片段
type:compaction                       # 只看压缩事件
```

结果带相关度分数、事件类型、`seq` 与居中片段；片段里被 `«»` 括起的是命中的词（不是原文的一部分）。随后用 `context_expand({ from, to })` 读取前后文。

## 配置

插件页 → 选中本插件 → 配置（`cordis.patch.yml` 中的行配置）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `recentUserMessages` | `2` | 锚点里保留多少条最近指令 |
| `recentFiles` | `3` | 锚点里列出多少个涉及文件 |
| `quoteChars` | `130` | 每条指令引用多少字符 |
| `maxAnchorChars` | `1000` | 锚点总字符上限 |
| `expandMaxChars` | `60000` | `context_expand` 的 `maxChars` 上限（默认单次输出 4000 字符） |

面板策略（存于 `~/.dsh/storages/context-anchor/settings.json`）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `mode` | `auto` | `auto` 跟随系统默认；`custom` 使用自定义阈值 |
| `percent` | `70` | 自定义压缩阈值（30–80） |
| `autoRecall` | `true` | 是否自动把归档片段带回锚点 |
| `protect` | `[]` | 保护关键词：命中这些词的那一段不折进检查点（最多 8 条） |

> **保护关键词**匹配大小写不敏感的子串，适合填文件路径（`src/auth/`）或模块名。命中时切分点前移到最近的一轮对话边界，命中的内容留在表层。有保底：若遵守规则会让可归档区间不足原来的四分之一，就按原切分执行——一条保护词不该让压缩彻底失效。

> 面板里的策略**按会话生效**：在哪个对话里改，就只影响哪个对话，写进 `settings.json` 的 `sessions.<会话 id>`；没有单独设置过的会话沿用顶层默认值。压缩判定与自动回忆都是按会话读取的，一个对话的阈值不会改变另一个对话的行为。

> 自定义阈值需要一个可用的压缩后端。若面板提示「当前环境没有压缩服务」，说明 profile 中 `@deepseek-ai/dsh-compaction-basic` 未启用；启用后自定义阈值立即生效。

### 面板里的只读信息

| 区块 | 含义 |
| --- | --- |
| 检索索引 | 本会话索引规模：多少篇文档、多少个词条（点开面板时实时读取） |
| 压缩次数 | 本会话**成功**压缩的累计次数，以及最近一次的 `seq`；失败的压缩不计入 |
| 分类记忆 | 七类记忆各有多少条（决定/约束/问题/待办/文件/命令/事实） |
| 本步注入 | 上一步锚点的实际开销：字符数、估算 token、是否含自动回忆、超预算被裁掉多少字符 |
| 历史趋势图 | 缓存占用率随时间的变化，最多 50 个采样点，随压力分级换色 |
| 下次压缩 | 若此刻触发压缩，会被折成检查点的那一段：`seq` 区间、条数、以及首尾两条原文摘录 |
| 建议 | 依据当前压力、阈值与索引规模给一条可执行的调整建议；没有值得说的就不显示 |

「下次压缩」用的切分规则与真正执行压缩时**完全同一份代码**（`archiveRegionOf`），所以面板上的承诺就是实际会发生的事：从不分割工具调用/结果对，也永远不会把正在进行中的那条指令折进去。

面板底部还有 **导出**/**导入**（JSON，含全局默认与全部会话策略）、**重置为全局**（删除本会话覆盖）与 **清除所有会话策略**（一次清空全部覆盖，带确认）。按 `Esc` 关闭面板。

面板高度封顶在视口之内（以徽标锚点为界），内容多时**在面板内部滚动**；面板标题与徽标悬停提示都带有版本号，用来确认页面运行的是哪份代码。

### 关于 token 开销

这个插件**不是无条件省 token**：锚点每一步都会注入系统提示，自动回忆也会把归档原文带回表层，这两项都是输入开销。它换来的是压缩后不失忆，以及不必反复检索。

能省的部分在于：

- **锚点默认上限已收紧到 1000 字符**，只保留最近 2 条指令、3 个文件、上一步动作的短摘要；完整会话计数、长路径与操作次数不再每步重复。
- **自动回忆只在强相关时注入**：最多 2 段、单段约 110 字符，弱匹配与重复片段不注入；运行时检查点（`Current runtime context. …`）不进入锚点、也不参与召回。
- **`context_expand` 默认单次 4000 字符**，先小幅读上下文，不够再续读，避免一次把整段归档历史重新塞回表层。
- **中文停用二元组不建索引**（的/了/是、这个/可以/就是…），并跳过出现在半数以上文档里的查询词：这类词区分不了段落，只会把无关片段顶上来。
- **压缩阈值越低不等于越省**：压缩本身要生成摘要，压得太早会更频繁地重新检索。收益取决于会话长度、压缩后大小与召回量。
- **超预算时按优先级裁剪，而不是砍尾巴**：各段带优先级，先丢最便宜、最容易用工具补回来的（任务计数、文件、上一步），再丢自动回忆，最后才截断正文；页脚（回到日志的入口）与当前指令永不丢。面板会显示「已裁 N 字符」。

面板里的「本地缓存 ~N」是**可召回内容的规模**（以及按同一密度估算的 token），不是「已经节省的 token」。真实费用还取决于模型的缓存命中定价，本插件没有计费数据，不作节省比例承诺。

面板的「本步注入」显示上一步锚点的实际开销：字符数、按 4 字符/token 估算的 token，以及这一步是否带上了自动回忆。它衡量每步新增的输入，与「可召回内容」表示的存量是两件事；尚未发过消息的会话显示「尚未注入」。

### 面板打不开时的自诊断

面板挂在 React 错误边界之后：渲染或 effect 崩溃时不再静默消失（表现为"点了没反应"），而是弹出一个红色提示框，写明具体错误，并上报到宿主端的 `trace.jsonl`（`clientError` 条目）。排障时先看红框文字，再用 `Get-Content ~/.dsh/storages/context-anchor/trace.jsonl -Tail 5` 读完整堆栈。

> 已知环境差异：插件加载器给客户端提供的 `window` 是一个不含 DOM 事件方法的垫片。客户端代码对 `window.confirm` 之类做了守卫，事件监听会先尝试 `globalThis` 再回退；新增 window/document API 的使用时应沿用同样的"先探测、可降级"写法。

## 分类记忆

锚点是**每步都要付钱的摘要**；分类记忆是**按需取用的库存**。日志到达时就被归类，不再额外调用模型：

| 分类 | 收什么 | 来源 |
| --- | --- | --- |
| 决定 | 选了哪个方案、结论是什么 | 助手消息（`决定`/`改用`/`结论`/`decided`…） |
| 约束 | 用户立的规矩、偏好、禁止项 | 用户消息（`必须`/`不要`/`只能`/`never`…） |
| 问题 | 报错、失败、卡住的地方 | 用户与助手消息（`报错`/`失败`/`TypeError`/`at fn (…)`…） |
| 待办 | 还没做完的事、下一步 | 双方（`TODO`/`还需要`/`接下来`…） |
| 文件 | 动过且值得记住的文件路径 | 工具调用参数里的 `file_path`/`path` |
| 命令 | 可以重跑的命令行 | 工具调用参数里的 `command`/`cmd` |
| 事实 | 项目与环境的稳定描述 | 用户消息里没有命中其他规则的陈述 |

模型这样取：

```
context_memory()                        # 全部七类，每类最新 8 条
context_memory({ kind: 'constraint' })  # 只看约束
context_memory({ query: 'addEventListener' })  # 跨类按词过滤
```

返回每条都带 `seq`，需要原话时再用 `context_expand` 展开。

分类是**固定规则**而非模型判断，因此 fork/resume 后结果一致，也不产生额外 token。代价是规则覆盖有限：反讽、隐含约定、跨句推理都抓不到，宁可漏也不归类错——错误记忆比没有记忆更糟。每类上限 40 条，超出丢弃最旧的；同一句话重复出现只存一次。

### 跨会话保留

会话结束后仍然成立的记忆会写进 `~/.dsh/storages/context-anchor/memory.json`，新会话开始时先载入、再叠自己的日志：

| 保留 | 不保留 |
| --- | --- |
| 约束、决定、事实 | 待办、文件、命令、问题 |

理由是后四类都属于**正在做的事**，换个对话就是噪音。每类最多 60 条。写入只在该类别集合真的变化时发生，不会每一步都重写文件。

被继承的条目在 `context_memory` 里显示为 `[早前会话]` 而不是 `seq`，因为它们不在本次日志里，`context_expand` 读不到。

删除这个文件就能清空跨会话记忆；面板上的「分类记忆」统计会把继承来的条目一并计入。

## 架构

```
┌─ Host 半（index.js）──────────────┐    ┌─ Client 半（client.js）───────────┐
│ systemPrompt.context → 锚点        │    │ conversation.composer.dock        │
│ tools: context_recall / expand     │    │   └ 「本地缓存 ~N」徽标            │
│ 检索内核：倒排索引 + BM25           │    │ shell.overlay                     │
│ agent/pre-step → 早期压缩           │←→  │   └ 面板（策略/状态/压力）         │
│ 投影 contextAnchorCache            │    │ 同源路由 /api/dsh-context-anchor   │
└───────────────────────────────────┘    └───────────────────────────────────┘
```

- **索引**：每会话增量维护，latin 词 + 中文二元组（中文无词边界），BM25 打分，短语加权。
- **数据来源**：宿主投影 `contextAnchorCache`（可召回规模）与 `contextPressure`（热上下文占用）。
- **策略读写**：客户端通过带连接校验的同源路由 `/api/dsh-context-anchor/settings` 与主机端交换 JSON。

```bash
npm test                # 全部自检，提交前必须全绿
```

它依次运行：

| 脚本 | 覆盖 |

| `probe-client.mjs` | 客户端渲染探针：槽位注册、点击链路、面板文案、趋势图 |

| `test/highlight.mjs` | 检索片段命中标记：预算、去重、大小写 |
| `test/render-smoke.mjs` | 面板各分支渲染：空历史、无热上下文、策略不可用、建议与预览 |
| `test/token-budget.mjs` | 输入开销预算：锚点上限、停用词、扩展开销、`已定：` 规则行 |
| `test/memory.mjs` | 分类记忆：七类归置、去重、按类/词/条数收窄、重放可复现 |
| `test/truncation.mjs` | 超预算时的裁剪顺序：先丢便宜的，保住回忆与页脚 |

> 所有接触插件的测试都先 `import './isolate.mjs'`，它把 `DSH_HOME` 指到临时目录。否则测试会写进你真实的 `~/.dsh/storages/context-anchor/`。

> 渲染类自检的价值在于**真的调用组件**。`node --check` 只证明能解析：一次 `cache` 写成未定义变量，语法全绿、探针也全绿（fixture 恰好没走那条分支），但真机上点开面板直接白屏。新增面板分支时，请让探针的 fixture 带上对应数据。

```bash

```

## 兼容性与已知限制

- 面向 DSH `0.2.x`；依赖 `sessionProjections`、`shell.overlay`、`conversation.composer.dock`、`contextPressure`、`agent/pre-step`。
- 检索是**词法**的（子串 / 二元组 / 正则），没有向量语义检索。
- 自动回忆只保证把最相关的几段摆到模型眼前，不保证它一定采用；深挖仍需模型自己 `context_expand`。
- 客户端样式全部内联（动态 Client 端没有 CSS 模块），悬停高亮由 React 状态实现。
